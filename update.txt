🎯 Core Architecture

Output Format (Written Reasoning): The system outputs a detailed written explanation for every insider purchase signal. Each explanation includes key details such as the ticker, insider name, insider role, transaction value, company market cap, sector, the price difference (gain or "discount" percentage from purchase price to current price), and a calculated moonshot score indicating signal strength. This human-readable output ensures you immediately understand why a particular insider trade is noteworthy.
Example: 🚀 MOONSHOT: Micro-cap $250M | Form 4 purchase of 50K shares @ $2.50 (Current: $2.75, +9.1%) | 🔥 Sector bonus: Biotechnology (+20)

Behind-the-Scenes Decision Making: The system applies several logical filters and a scoring algorithm to identify high-value signals from raw insider trading data:

Transaction Filters: Focuses only on open-market purchases (Form 4 code "P") within a target price range (e.g. $1–$50 per share) and a minimum total trade value (e.g. ≥ $50K). This weeds out irrelevant filings like option grants or trivial trades.

Market Cap Gating: Categorizes opportunities by company size. Insider buys in smaller companies (market cap < $2B) are flagged as potential “moonshots” due to higher growth volatility, whereas buys in larger companies (market cap > $2B) are still captured but labeled separately as high-conviction signals. This distinction helps focus on the explosive micro-cap opportunities while still tracking big-cap insider confidence.

Scoring Algorithm: Each signal is assigned a moonshot score based on multiple factors — the purchase size (relative to typical trades), the insider’s role (e.g. CEO purchases score higher than a director’s), the price difference (if the insider’s buy price is at a discount or premium to current price), the company’s market cap (smaller cap yields a higher score), the sector’s momentum or relevance (certain sectors might get a positive “🔥 sector bonus”, e.g. biotech), and accumulation patterns (repeat or cluster buying by the same or multiple insiders). A higher score (out of 100) indicates a more significant signal. All these elements combine to highlight only the most impactful insider trades.

📊 Required Inputs and Data Sources

SEC EDGAR Form 4 Filings: Insider transactions are obtained through the SEC’s EDGAR system (e.g. via a free Form 4 RSS feed). The system parses the XML filings to extract details like the ticker, insider name, insider role (officer, director, 10% owner, etc.), transaction type and code, number of shares, price per share, and transaction date. Only relevant open-market purchase entries are kept for analysis.

Yahoo Finance API (or similar): To enrich the insider data, the system pulls current market data for each ticker. This includes the company’s market capitalization, sector and industry classification, current stock price, recent trading volume, and 52-week high/low if needed. These data points provide context (e.g. company size and sector) and allow calculation of metrics like the price change since the insider’s purchase.

Data Structure for Signals: Each insider buy signal is encapsulated in a structured format (e.g. a Python dictionary) that the system can easily process or output. For example:

{
    "ticker": "SYMBOL",
    "insider_name": "John Doe",
    "insider_role": "CEO",
    "transaction_value": 100000,         # $ amount of shares purchased
    "market_cap": 500000000,             # company market cap in dollars
    "sector": "Biotechnology",
    "moonshot_score": 85,                # calculated significance score
    "reasoning": "Full explanation string describing the signal"
}


Every signal object includes the raw data (who bought, how much, etc.), the contextual data (market cap, sector), the computed moonshot score, and the reasoning string which is the human-readable explanation. This structure makes it easy to filter or further process signals in code, while also providing immediate readability.

🔄 Integration Points

To support advanced features and user-specific workflows, the system includes several integration points:

Database Layer (SQLite): All parsed insider transactions can be stored in a local database (e.g. an SQLite table insider_transactions). This persistence enables tracking of accumulation patterns over time. By querying this database, the system can detect if the same insider has made multiple purchases in recent periods or if multiple insiders at the same company are buying (a bullish cluster buying signal). This historical context can boost the score or highlight repeat signals, since repeat purchases often indicate stronger conviction. The lightweight database also prevents duplicate processing of the same filings and can be extended for record-keeping or performance analysis.

Alert/Notification System: The system can be configured to generate alerts for high-priority signals. For example, you might set triggers to notify you (via email, SMS, or dashboard) whenever an insider buy has a moonshot score ≥ 80 or the transaction value ≥ $500K. Alerts can be categorized so that small-cap “🚀 Moonshot” opportunities are emphasized separately from large-cap “Conviction” signals. This way, you won’t miss a major insider purchase — whether it’s a tiny biotech or a Fortune 500 executive buy — and you can tailor your attention to the type of signal (high-growth speculative vs. strong-confidence blue-chip insider buy).

Scheduling and Automation: The monitor is designed to run on a schedule, ensuring timely updates as new filings come in. For example, you could schedule the system to run 4 times daily (e.g. at 8:00 AM, 12:00 PM, 4:30 PM, and 10:00 PM ET) to fetch and process any new Form 4 filings throughout the day. Built-in caching or state management prevents re-processing the same filing twice. This regular cadence guarantees that any impactful insider purchase is flagged shortly after it’s publicly disclosed, without manual intervention. You can adjust the frequency as needed (even real-time streaming of the RSS feed is possible if desired).
